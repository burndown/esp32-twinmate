# Validation record

**English** · [中文](VALIDATION.zh-CN.md) · [Back to README](../README.md)

This page preserves test records dated 2026-10-21 from the previous README. No deployment, firmware build or device flash was repeated while editing the documentation. “Passed” below refers to the previously recorded results.

## Build and deployment

- The patch applied to clean upstream commit `fa07304`. Settings were generated from `muse-cloud.toml` and the firmware built from scratch with the patch features and new partition, including a build with WireGuard enabled.
- The tool commands `init`, `check`, `gateway`, `status` and `firmware` were exercised. The gateway was deployed to a real free Cloudflare account; the test Worker was deleted afterwards.

## Muse voice interaction after flashing with the tool

A Waveshare ESP32-S3-Touch-AMOLED-1.75C was flashed using `firmware --flash` with `wireguard.enabled = false` and completed one Muse interaction. Recognition used Cloudflare Whisper and synthesis used Azure, both through the deployed Worker.

| Measurement | Recorded result |
|---|---|
| Question | One sentence, 11 Chinese characters |
| Reply speech requests | 20 |
| Playback duration | 55 seconds |
| Total interaction time | 135 seconds |
| Lowest free internal memory | 12 KB |

The first attempt failed because the tool omitted `CONFIG_ESP_NETIF_BRIDGE_EN`. The device restarted about every 4 seconds and lost its pairing. The firmware was changed to require that setting, the device was paired again in the Muse app, and the second attempt passed.

## Rebuild and pairing after erasing the entire flash

The same board's entire flash was erased to `0xFF`. The tool fetched the upstream source, applied the patch, built and flashed from scratch. The device entered pairing mode and, after pairing in the Muse app, completed recognition, a Muse reply and synthesis in 39 seconds without a restart.

The board's factory data partition had originally been empty. **This test does not replace first-use testing on a new, out-of-the-box board**.

## Scenarios not yet covered

- A Grok Bot reply on the device after flashing with the tool. The Worker-side bot flow has been tested, but that does not establish that this device flow passed.
- WireGuard enabled on the device with a key generated by the tool. A successful build does not establish a working device connection.
- A user with no related experience completing setup using only the README.
- Initial flashing and pairing on a new, out-of-the-box board.
- Other boards and native Windows. The tool calls ESP-IDF's `export.sh` through `bash`, so Windows may require WSL.
